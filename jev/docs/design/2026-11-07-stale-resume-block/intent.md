# Intent: Stale-resume block
Status: implemented · Date: 2026-11-07

## Problem
오래 쉰 메인 세션을 재개하면 첫 프롬프트 한 번에 만료된 캐시 전체가 다시 써집니다. 2026-11 토큰 감사에서는 10일 쉰 세션을 재개하자 195K 토큰이 한 번에 재작성되어 Opus 기준 $1.56이 들었습니다(Pro 계정이라 사용량 한도 소모와 같습니다). 사용자는 보내기 전에 이 비용을 알 수 없고, "1시간 안에 재개" 규칙은 서브에이전트에만 적용되어 메인 세션은 다루지 않습니다.

## Goals
- G1. 1시간 넘게 쉬었고 컨텍스트가 100K 토큰을 넘는 세션에서 프롬프트를 보내면, 그 프롬프트는 모델로 가지 않고 막히며 사용자는 예상 재작성 토큰 수와 금액, 그리고 상태 파일에서 새 세션을 시작하라는 제안을 봅니다.
- G2. 같은 공백에서 같은 프롬프트를 다시 보내면 그대로 진행됩니다. 공백 하나당 차단은 한 번뿐입니다.
- G3. 조건에 맞지 않는 세션(짧은 공백, 작은 컨텍스트, 무인 실행)은 아무것도 달라지지 않습니다.
- G4. 오케스트레이션 규칙의 "Long work"에 메인 세션 재개 기준이 한 줄 들어갑니다.

## Non-goals
- 컨텍스트 요약이나 상태 파일을 자동으로 만들지 않습니다.
- 캐시 TTL 설정은 바꾸지 않습니다.
- 서브에이전트 재개는 다루지 않습니다(기존 규칙이 다룸).

## Constraints and assumptions
- 훅이 실패하면 프롬프트를 막지 않습니다(fail-open).
- 기존 UserPromptSubmit 훅 진입점(agent-hooks)과 시작 모델 추천(main-pick)을 그대로 둡니다.
- Assumption: 메인 세션의 캐시 TTL은 1시간입니다. 감사에서 60분 이하 공백은 재작성이 없었습니다.
- Assumption: 단가는 감사 단가표의 1시간 캐시 쓰기 가격입니다(Opus $8/M, Sonnet $4/M). 다른 모델은 금액 없이 토큰 수만 보입니다.
- Assumption: UserPromptSubmit 훅의 차단은 API 호출 전에 일어나므로 재작성 비용을 실제로 막습니다.
